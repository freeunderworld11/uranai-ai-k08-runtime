# CASE_F 太陽サイン境界（2026-09-11）

東京の固定座標（北緯35.6762、東経139.6503）で、2000-03-20 16:35:14と16:35:15（Asia/Tokyo、+09:00）を架空の出生入力にします。対応するUTCは07:35:14と07:35:15。公式swetest64 2.10.03の参照黄経は359.9999925度と0.0000040度で、魚座から牡羊座への境界を挟みます。

固定入力・期待値はtest/fixtures/case-f-before.jsonとcase-f-after.json、取得出力は対応する-native.txt、生成処理はscripts/prepare-case-f-before.pyとprepare-case-f-after.pyです。実行引数・実行ファイルSHA-256を保存し、端末固有パスだけを置換しています。配布データ0.2.2を使う別nativeプロセスから10天体黄経・速度、ASC/MC、12カスプを取得しました。45組のアスペクト成立種類・不成立はnative黄経から別のPython処理で算出し、Worker出力を期待値に使用していません。通常テストで期待値を再生成しません。

共通照合の許容差は黄経0.01度、ASC/MC・カスプ0.05度、速度0.000001度/日。速度は開発用条件でありK19正本の規定値ではありません。アスペクト成立種類・不成立は完全一致を要求します。

境界専用の追加検査では太陽の黄経差を1e-6度未満とし、数値の許容差だけで逆側のサインを通さないよう、PISCES/ARIESの期待値を直接比較します。境界感度が両側trueであること、正式結果ブロックにも同じサインが記録されることを検査します。表示丸めでサインを決めません。既存の春分境界探索テストも引き続き実行します。

全81テストがローカルWorkers互換環境で成功しました。これは同じSwiss Ephemeris系列・同じデータによる回帰一致であり、境界時刻の絶対UTC精度や出生時刻の精度の認証ではありません。K02の状態はfixtureの申告です。本番承認・K19全体の受入は保留し、K09_USAGE_STATUSはLOCAL_BLOCKです。

CASE_Fはサイン境界の両側の出生図照合を目的とします。CASE_Kの0度牡羊近辺は未完了のままとし、別の受入目的を定めて検証します。次はCASE_G（月サイン境界）です。
